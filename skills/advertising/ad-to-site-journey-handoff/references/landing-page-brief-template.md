# Landing-page brief template

When to read: whenever a campaign needs a destination page, or an existing page is being repaired.

A landing page is a page that is not the home page, built to elicit one key action from a defined traffic source (Levy 2015). It must convey the value proposition about as fast as a short commercial.

## 1. Brief fields

| Field | Content |
|---|---|
| Journey ID | Campaign, ad set / ad group, audience temperature |
| Page job (one) | e.g. "Book a free 20-minute consultation" |
| Conversion event and value | From the measurement spec |
| Audience and awareness level | Cold / warm / retargeting; unaware → most aware |
| Message-match table | Each ad headline/hook and the page element that answers it |
| Headline and sub-headline | Echo the ad's promise in the visitor's words |
| Offer block | Offer, price and terms (or "from" price for premium), deadline with its real reason |
| Proof | Consented testimonials, results with source and date, certifications, reviews; place near the top |
| Objections and answers | Top three objections, each answered on the page (FAQ or inline) |
| Primary CTA | Label and destination; one primary action |
| Secondary contact | Phone and WhatsApp click-to-chat with response-time promise |
| Form spec | Fields actually used by sales; one qualifying question if needed; consent text; privacy link; no pre-ticked boxes |
| Thank-you / confirmation state | What happens next, when, by whom; conversion fires here |
| Mandatories | Legal lines, disclosures, regulated-category text |
| Mobile and speed acceptance | CW-01 Core Web Vitals targets and CW-04 stress profile; owned and reported by the web team |
| Accessibility acceptance | WCAG 2.2 AA (CW-05); captions, alt text, contrast |
| Languages | Transcreated versions and reviewers |
| Variants for testing | Which element varies (headline, proof order, offer) |
| Owners and dates | From the RACI |

## 2. Page structure (default, adapt to awareness level)

1. Headline matching the ad + one-line sub-headline with the outcome.
2. Proof strip (one or two strongest consented proofs).
3. Offer and primary CTA; human contact route visible.
4. How it works (three steps) or what you get.
5. Objection answers.
6. More proof (case story, reviews).
7. Guarantee (process guarantee for services).
8. Final CTA restating the opening benefit.

Cold traffic usually needs more education and story before the offer; warm and retargeting traffic can lead with the offer.

## 3. Landing-page experiment (Levy 2015, five steps)

1. Define the experiment: which part of the value proposition or journey is tested; is it value-proposition testing, a pivot or lead acquisition?
2. Build the page to convey the proposition quickly; plan the thank-you page with next steps and a phone or WhatsApp route for nervous users.
3. Build variants to test propositions, copy or layout patterns.
4. Run a controlled campaign with set boundaries: budget cap, keywords or audiences, ad copy, demographics, start and end dates.
5. Measure: click-through, conversion, cost per conversion, sharing; decide with the lines set in `ad-testing-and-scaling`.

## 4. Pricing and choice presentation on pages (Wiebe 2011)

- Show 2–4 options, never one; group like options; align feature rows; one true highlight ("Most chosen" only if literally true); place the plan you most want to sell in the middle on desktop and badge it first on mobile.
- Subordinate "Free"; offer a trial or guarantee where the eye lands (below price, above button).
- Premium offers build value before price; commodity offers show price early; discounts show old price, new price and saving together.
- Put a human contact line directly below any pricing table.
